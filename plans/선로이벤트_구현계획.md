# 선로 이벤트(게임 중 이벤트) 구현 계획

작성일: 2026-10-26
상태: **구조(뼈대)만 — 씬 배치·UI·이벤트 효과 대부분 미구현**

---

## Context

전투 구간(역 → 역)이 매번 같은 리듬이라 중후반이 단조롭다. 구간 도중 무작위로 "선로 이벤트"를 터뜨려 위기/기회/선택의 변주를 준다.
기존에 `StageManager._StartMonsterRush()`(고정 주기 몬스터 러시)가 사실상 유일한 이벤트였는데, 이걸 일반화한 틀을 만든다.

**원칙**
- 기존 흐름(`EngageStartEvent` → 전투 → `InspectionStartEvent` 상점)을 건드리지 않고 **옆에 붙인다.** StageManager 수정 없음.
- 이벤트는 **역 도착 시 반드시 끝난다.** → 런 세이브(역 도착 시 저장)에 상태를 넣을 필요가 없다.
- 순수 C# 추첨 코어 + MonoBehaviour 어댑터 분리(`SkillTreeCore`/`SkillTreeManager`와 같은 패턴).
- 한 구간에 이벤트는 최대 1개.

## 1. 이번에 만든 구조

```
Assets/01_Scripts/Game/
├─ Datas/TrackEvent/
│   ├─ TrackEventType.cs        이벤트 종류 enum (기획 아이디어 7종 슬롯)
│   └─ TrackEventData.cs        정적 정의 (id·가중치·등장 조건·지속시간·세기·로컬라이즈 키·아이콘)
├─ Events/
│   ├─ TrackEventStartEvent.cs  발동 알림 (UI·사운드·분석용)
│   └─ TrackEventEndEvent.cs    종료 알림 (IsInterrupted = 역 도착/게임 종료로 끊김)
├─ TrackEvent/
│   ├─ ITrackEventEffect.cs     효과 인터페이스 Begin / Tick / End
│   ├─ TrackEventScheduler.cs   순수 C# 추첨 코어 (확률·가중치·발동 시각·직전 중복 방지)
│   ├─ TrackEventEffectFactory.cs  타입 → 효과 매핑 (미구현 타입은 null → 후보에서 제외)
│   └─ Effects/MonsterRushTrackEventEffect.cs  예시 구현 (기존 MonsterRushEvent 재사용)
└─ Manager/TrackEventManager.cs 오케스트레이터 (Singleton)
```

### 흐름

```
EngageStartEvent ─→ TrackEventManager._OnEngageStart (구간당 1회만)
                     └ 누적 상점 수 < firstEventStationCount 면 스킵
                     └ Scheduler.RollSegment(확률 eventChancePerSegment, 구간 길이 × [0.2~0.6] 시점 예약)
FixedUpdate (InGameSequence.IsRunning 일 때만 — 일시정지·레벨업 중엔 시간 안 흐름)
   ├ Scheduler.Tick → 예약 시각 도달 → Effect.Begin + TrackEventStartEvent
   └ ActiveEffect.Tick → duration 만료 → Effect.End(false) + TrackEventEndEvent
InspectionStartEvent / GameOverStartEvent / GameEndEvent
   └ 예약 취소 + Effect.End(true) + TrackEventEndEvent(IsInterrupted=true)
```

### 튜닝 노브 (TrackEventManager 인스펙터)

| 필드 | 기본값 | 의미 |
|---|---|---|
| `isEnabled` | true | 전체 on/off |
| `eventChancePerSegment` | 0.35 | 구간당 발동 확률 |
| `firstEventStationCount` | 2 | 이 누적 상점 수 전엔 이벤트 없음 (튜토리얼·첫 역 보호) |
| `minTriggerTimeRatio` / `maxTriggerTimeRatio` | 0.2 / 0.6 | 구간 길이 대비 발동 시각 범위 |
| `eventDatas` | — | 이벤트 정의 목록 |

## 4. 이벤트 아이디어 (우선순위 순)

> 분류: 🔴 위기(압박↑) / 🟢 기회(보상) / 🟡 선택(리스크·리턴)
> "필요 인프라"가 기존 코드로 되면 먼저 만든다.

| 순위 | 이벤트 | 분류 | 내용 | 필요 인프라 | 난이도 |
|---|---|---|---|---|---|
| 1 | **몬스터 러시** `MonsterRush` | 🔴 | 역까지 스폰 간격 ×0.5. 기존 WarningUI 경고 | ✅ 구현됨 (`MonsterRushEvent`) | 완료 |
| 2 | **과부하 운행** `Overdrive` | 🟢 | 10초간 전 포탑 공격속도 +50%. 기차 배기 이펙트 | 전 포탑 시한 버프 — 엘리트 포탑 계획의 **E 시한 버프** 인프라와 공유 | 중 |
| 3 | **보급 상자** `SupplyDrop` | 🟢 | 선로 옆에 상자 1~3개 떨어짐. 터치하면 골드(현재 골드 스케일 × magnitude). 8초 뒤 사라짐 | 터치 가능한 월드 오브젝트(풀링 `ResourceManager`), 골드 지급 경로 | 중 |
| 4 | **엘리트 매복** `EliteAmbush` | 🔴🟢 | 즉시 엘리트 1마리 출현, 처치 시 엘리트 재화 ×2 | `MonsterSpawner`에 "엘리트 1마리 즉시 스폰" 공개 API 추가 | 중 |
| 5 | **황금 몬스터** `GoldenMonster` | 🟢 | 반대 방향으로 도망가는 금색 몬스터. 화면 밖으로 나가기 전에 잡으면 큰 골드 | 이동 방향 반전 몬스터 변형, 이탈 판정 | 중상 |
| 6 | **모래폭풍** `Sandstorm` | 🔴 | 15초간 포탑 사거리 −30% + 화면 노이즈 오버레이 | 포탑 사거리 배율 훅 (`TrainRangeIndicator`도 갱신) | 중 |
| 7 | **우회로 선택** `DetourChoice` | 🟡 | 일시정지 후 2지선다 — "위험한 지름길: 구간 −30%, 몬스터 HP +20%" / "안전한 길: 변화 없음" | `OverlayPhase`에 이벤트 선택 단계 추가, 구간 시간 단축 API(StageManager 수정 필요) | 상 |

### 추가 후보 (검토용)

- **떠돌이 상인** 🟡 — 구간 중 작은 팝업 상점(1개 상품, 할인). 상점 시스템 재사용 가능한지 검토 필요
- **선로 고장** 🔴 — 맨 뒤 칸 포탑 5초 정지. 터치 연타하면 빨리 복구 (조작 재미)
- **유성우** 🟢 — 화면 무작위 위치에 폭발, 몬스터만 피해. `PlayerBombardManager` 폭격 재사용
- **안개** 🔴 — 몬스터 체력바·데미지 숫자 숨김 (스탯 변화 없이 긴장감만)
- **연쇄 이벤트** — 특정 이벤트 클리어 시 다음 구간 보상 이벤트 확정 (업적 연동)

### 밸런스 가이드

- 위기 : 기회 : 선택 ≈ 4 : 4 : 2 가중치로 시작, 분석 로그로 사망 구간과의 상관을 보고 조정
- 위기 이벤트는 `minStationCount`를 높게(5+) — 초반 이탈 방지
- 보상량은 고정값이 아니라 `StageManager`의 골드 스케일(누적 상점 수)에 비례시켜 후반에도 의미 있게

## 5. 열린 질문 (기획 결정 필요)

1. 기존 `StageManager.monsterRushInterval`(N역마다 고정 러시)을 유지할지, 선로 이벤트의 러시로 대체할지
2. 이벤트 발동 시 게임을 멈추고 알릴지(튜토리얼처럼), 멈추지 않고 배너만 띄울지 — 현재 구조는 "멈추지 않음" 전제
3. 이벤트 등장 여부를 영구 업그레이드/스킬트리로 늘리는 메타 성장 연결을 할지 (예: "행운의 선로: 이벤트 확률 +10%")
