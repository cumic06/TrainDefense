# 총알(투사체) 능력 조합 확장성 개선 설계

작성일: 2026-06-15
상태: **설계만 — 구현 미진행**

---

## Context

현재 기차의 "총알 능력"(투사체 교체 / 관통 / 크기 / 넉백 등)을 섞을 수 있는 범위가 한정적이다.
원인은 총알 커스터마이즈가 **서로 다른 3개의 비호환 경로**로 처리되고, 그중 대부분이
`TurretTrain` 전용이며, 여러 능력이 **합쳐지지 않고 덮어쓰기/우선순위로만 동작**하기 때문이다.

이 문서는 총알 능력을 **합성 가능한 레이어(modifier pipeline)** 로 재설계하여
"기관총탄 + 관통 + 폭발 + 분열"처럼 자유롭게 섞을 수 있게 만드는 방향을 정의한다.

**원칙**: 기존 `TurretTrain`/`RangeTrain`/`Projectile`/`TrainPassiveSkill` 인프라 재사용.
패시브 → 총알 적용 경로를 단일화하고, 기차 종류에 독립적으로 만든다.

---

## 현재 구조 (코드 기준)

총알 능력은 패시브(`TrainPassiveSkill`)가 `Subscribe()` 시점에 기차에 직접 붙는다.
총알을 바꾸는 방법은 현재 **3가지**다:

### 경로 ① 통짜 프리팹 교체 (`GetOverrideProjectile`)
- `TurretTrain.cs:48-49` — `ProjectileOverrideProvider` 델리게이트 리스트
- `TurretTrain.cs:359-367` — 등록된 provider를 순회하며 **첫 non-null 반환**
- `TurretTrain.cs:812` — 발사 시 override가 있으면 그 프리팹을 통째로 사용
- 사용처: `OverrideEveryNAttacksPassive.cs:32`(N발마다 교체), `PierceProjectilePassive.cs:27`(관통)

### 경로 ② 기차 레벨 스칼라 필드
- `TurretTrain.cs:56-58` — `ProjectileScale`, `ProjectileKnockbackPower`, `ProjectileKnockbackDuration`
- `TurretTrain.cs:840-844` — 발사 시 스폰된 투사체에 적용
- 사용처: `ScaleProjectilePassive.cs:23`(크기), `KnockbackOnHitPassive.cs:24`(넉백)

### 경로 ③ 발사 이벤트 훅
- `TurretTrain.cs:60-61` — `OnAttacked`, `OnTargetPosAttacked`
- 사용처: `FollowUpExplosionPassive`(후속 폭발), `RandomPosBombardPassive`, `RepeatAfterAttackPassive` 등

### 데이터 정의
- `TrainSkillProjectileData.cs` — `projectilePrefabId / damage / range / projectileCount`
- 패시브 파라미터: `TrainPassiveSkillData.cs:16-20` — `param1~3` (3개 고정)
- DSL 파싱: `TrainPassiveSkillFactory.cs` — 12종 파서 하드코딩 (`Register()` API는 존재)

## 한정적인 이유 (총알 한정 진단)

| # | 문제 | 위치 | 영향 |
|---|------|------|------|
| **1** | **프리팹 교체가 합성 불가** — `GetOverrideProjectile`이 첫 non-null만 반환 | `TurretTrain.cs:361-366` | 관통탄 + 폭발탄을 동시에 못 씀. 두 override 패시브를 붙이면 **하나만 적용**되고 나머지는 조용히 무시 |
| **2** | **수식 필드가 덮어쓰기(last-writer-wins)** — `ProjectileScale` 등이 단일 float | `TurretTrain.cs:56-58` | 크기 패시브 2개 → 누적 안 됨. 해제 시 `= 1f`로 리셋해 다른 패시브 값까지 날림 (`ScaleProjectilePassive.cs:28`) |
| **3** | **TurretTrain 전용** — `RangeTrain`엔 override 훅/스칼라 필드 자체가 없음 | `RangeTrain.cs:31` (`OnAttacked`만 존재) | 총알 능력 패시브를 RangeTrain에 붙여도 `if (Owner is TurretTrain)`가 false → 무동작 |
| **4** | **능력당 1개 슬롯** — 선택 시 패시브 1개만 적용 | `Train.cs:365` (`_IsPassiveApplied`) | 애초에 총알 능력 여러 개를 한 기차에 못 얹음 (조합 게임플레이 자체가 막힘) |
| **5** | **파라미터 3개 / 파서 하드코딩** | `TrainPassiveSkillData.cs:16-20`, `TrainPassiveSkillFactory.cs:14-40` | 복잡한 총알 능력 추가 시 데이터/코드 동시 수정 필요 |

→ **핵심**: 총알 능력은 "통짜 교체 + 덮어쓰기" 모델이라 **레이어로 쌓이지 않는다.**
이것이 "섞을 수 있는 게 한정적"인 직접 원인이다.

## 목표 설계: 투사체 수식 파이프라인 (Projectile Modifier Pipeline)

총알 능력을 **합성 가능한 modifier 리스트**로 통일한다.
프리팹 통짜 교체 대신, 베이스 총알 위에 여러 modifier를 순서대로 적용한다.

### 핵심 인터페이스

```csharp
// 기차 종류와 무관한 발사 컨텍스트
public struct ProjectileSpawnContext
{
    public int AttackIndex;       // 누적 공격 횟수 (N발마다 등)
    public Monster Target;
    public Vector3 SpawnPosition;
    public Vector3 AimDirection;
}

// 합성 가능한 총알 수식자
public interface IProjectileModifier
{
    int Order { get; }   // 적용 순서 (프리팹선택 → 스탯 → 비주얼 순)

    // 베이스 프리팹을 바꾸고 싶을 때만 non-null 반환. null이면 이전 단계 유지.
    Projectile OverridePrefab(ProjectileSpawnContext ctx, Projectile current);

    // 스폰된 투사체 인스턴스에 누적 수식 적용 (크기/넉백/관통/데미지배수 등)
    void Apply(ProjectileSpawnContext ctx, Projectile projectile);
}

// Turret/Range 공통 — 총알을 쏘는 모든 기차가 구현
public interface IProjectileEmitter
{
    void AddProjectileModifier(IProjectileModifier modifier);
    void RemoveProjectileModifier(IProjectileModifier modifier);
}
```

### 발사 경로 통합

`SpawnNormalProjectile`(`TurretTrain.cs:807`)을 다음으로 교체:

```csharp
Projectile prefab = GetProjectile();
var ctx = new ProjectileSpawnContext { AttackIndex = _attackCounter, ... };

// 1) 프리팹 선택: 모든 modifier가 순서대로 교체 시도 (마지막 non-null 우선 or 우선순위)
foreach (var m in _modifiers)        // Order 정렬
    prefab = m.OverridePrefab(ctx, prefab) ?? prefab;

var projectile = ResourceManager.Instance.Spawn(prefab);
SetupProjectileTransform(...);
InitializeProjectile(...);

// 2) 누적 수식: 크기·넉백·관통·분열 등이 전부 쌓임
foreach (var m in _modifiers)
    m.Apply(ctx, projectile);
```

이렇게 하면:
- **문제 1 해결**: 관통·폭발·크기 modifier가 동시에 `Apply` → 합성됨
- **문제 2 해결**: 스칼라가 train 필드가 아니라 modifier가 들고 있어 덮어쓰기 없음.
  (필요하면 `projectile.AddScale(x)` 식 누적 API)

### 기존 패시브 마이그레이션

| 기존 패시브 | 신규 형태 |
|---|---|
| `OverrideEveryNAttacksPassive` | `IProjectileModifier`로 — `OverridePrefab`에서 `AttackIndex % N == 0`일 때 프리팹 반환 |
| `PierceProjectilePassive` | `Apply`에서 `projectile.SetPierce(...)` |
| `ScaleProjectilePassive` | `Apply`에서 `projectile.AddScale(...)` (누적) |
| `KnockbackOnHitPassive` | `Apply`에서 `projectile.SetRuntimeShove(...)` |

→ 패시브들은 `Subscribe()`에서 `if (Owner is TurretTrain)` 대신
`if (Owner is IProjectileEmitter e) e.AddProjectileModifier(this)` 로 변경.
**TurretTrain·RangeTrain 둘 다 `IProjectileEmitter` 구현 → 문제 3 해결.**

## 단계별 구현 계획

### Phase 1 — 인터페이스 + Turret 파이프라인 (호환 유지)
- `IProjectileModifier`, `ProjectileSpawnContext`, `IProjectileEmitter` 추가
- `TurretTrain`에 `_modifiers` 리스트 + `SpawnNormalProjectile` 파이프라인화
- 기존 `GetOverrideProjectile` / `ProjectileScale` 필드는 **어댑터로 위임**(기존 패시브 안 깨지게)
- 총알 modifier 4종(Override/Pierce/Scale/Knockback)을 신규 인터페이스로 재작성

### Phase 2 — RangeTrain 동등 지원 (문제 3)
- `RangeTrain`도 `IProjectileEmitter` 구현, 동일 파이프라인 적용
- 패시브의 `Owner is TurretTrain` 캐스팅 → `IProjectileEmitter`로 교체

### Phase 3 — 다중 슬롯 (문제 4)
- `_IsPassiveApplied`(`Train.cs:365`) / 선택 로직을 단일 → N개 누적 허용으로 확장
- 선택 UI에서 총알 능력 다중 획득/스택 가능하게

### Phase 4 — 데이터 확장 (문제 5)
- `TrainPassiveSkillData` `param1~3` → 가변(`string[] params` 또는 JSON)
- `TrainPassiveSkillFactory` 어트리뷰트 기반 자동 등록(`[PassiveSkill("...")]` + 리플렉션)
